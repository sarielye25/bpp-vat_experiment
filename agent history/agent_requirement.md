工作环境概况：

0. 其他文件夹会包含具体项目，项目内部也会有需要知道的基础信息，同一命名为info.txt，运行前需要读取。如果有agents.md等其他辅助文档也需要读取。
1. 本地只负责代码审阅与编辑，以及简单少量的工具性质脚本本地运行（比如数据简单预处理，可视化）如果特殊说明不要克隆代码到本地，就只在远端修改
2. 本地环境使用conda torch环境
3. 所有有关模型训练，推理等代码，仿真环境等，在远程服务器上完成。远程服务器使用docker管理。有多个服务器可供选择登陆。不要私自创建docker容器，所有容器级别操作应该用户确认完成。服务器提前由用户配置好登陆方式并且保存到本地文件信息，使用ssh登陆。
4. docker的data目录和dataset目录挂在到宿主机目录下，代码应该保存在data目录下，数据集应该保存在dataset目录下，避免换容器后数据重新下载
5. 尽可能使用modelscope下载模型，其次可以用huggingface，但是应该使用国内镜像网站，提升速度。模型不要下载到比如 .hf  .ms目录，而应该下载到dataset或者data目录，注意data目录下已经有hf专门保存模型权重文件
5. 所有代码的运行方式应该简单易懂。不要一个脚本支持十几个参数比如 ./start.sh --a 123 --b 321 --c 3132 --d 3213。如果参数不可避免，应该是包装在一个脚本里面比如 ./easy_start.sh 然后内部调用参数。并且需要注释说明。大多数情况下应该是python支持一些命令行参数，然后shell脚本来包装python脚本。应该使用配置文件来完成参数配置，而非通过临时的调用，因为这样会导致容易忘记之前跑的版本保存的什么参数
6. 跑实验的脚本需要用logs目录记录，最好可以支持配置文件指定logs下子目录名称，如logs/exp1  logs/exp2，然后下面以时间记录子目录，然后logs也需要记录配置参数。推荐使用hydra系统来管理配置
7. 在一些情况下，某些程序运行会导致内存暴涨（大概率是因为服务器cpu核心数量较多，一些程序就分配大量内存）注意这种情况下要及时发现停止，限制cpu或者内存资源
8. 除非用户说明：修改，修复，创建等等明确需要修改的任务指令，不需要直接开始修改代码
9. 视频一律使用 H.264（libx264，avc1）编码，不要用 OpenCV 的 mp4v（MPEG-4 Part 2）：后者 VLC 能播，但 VS Code 内置预览、浏览器和 Chromium/Electron 都解不了。Python 写视频统一用 imageio.get_writer(..., codec='libx264')，ffmpeg 转码加 -c:v libx264 -pix_fmt yuv420p -movflags +faststart
